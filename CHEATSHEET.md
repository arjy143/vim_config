# Vim Config Cheatsheet

**Leader key = `,`** (so `<leader>x` means press `,` then `x`).

A quick reference for every mapping and the most useful commands in this config.
Mappings marked **(default)** come from a plugin; the rest are defined in `.vimrc`.

> 💡 Press **`<leader>?`** (`,?`) inside Vim at any time to open this cheatsheet in a new tab.

---

## Setup / installation

Several plugins rely on external tools. On a fresh machine:

1. **Install [vim-plug](https://github.com/junegunn/vim-plug)** (plugin manager):
   ```bash
   curl -fLo ~/.vim/autoload/plug.vim --create-dirs \
     https://raw.githubusercontent.com/junegunn/vim-plug/master/plug.vim
   ```
2. **Install the plugins:** open Vim and run `:PlugInstall`.
3. **Install the external tools** below.
4. **Make the fzf binary available** (if `:Files` errors): `~/.vim/plugged/fzf/install --bin`.

### Required external tools (Ubuntu / WSL)
| Tool | Powers | Install |
|---|---|---|
| Universal Ctags | gutentags + `<C-]>` tag jumps | `sudo apt install universal-ctags` |
| clangd | C/C++ LSP via ALE (completion, go-to-def, diagnostics) | `sudo apt install clangd` |
| ripgrep (`rg`) | fzf `:Rg` / `<C-g>` search | `sudo apt install ripgrep` |
| glow | markdown preview (`,mp`) | release binary → `~/.local/bin/glow` (must be on `PATH`) |

### Optional / per-feature
| Tool | Powers | Install |
|---|---|---|
| clang-format | `:ALEFix` C/C++ formatting | `sudo apt install clang-format` (then add to `g:ale_fixers`) |
| pyright *or* python-lsp-server | Python LSP | `pip install pyright` / `pip install python-lsp-server` (add to `g:ale_linters`) |
| LLM server on `localhost:5000` | llm-complete ghost-text | run your own server (see `llm-complete/install.sh`) |
| debug adapter | vimspector | `:VimspectorInstall <adapter>` + a `.vimspector.json` |

### Per-project setup
Some features must be configured **inside each project**, not in the global `.vimrc`:

**C/C++ LSP (clangd)** needs a *compilation database* (`compile_commands.json`) at or
above the file — without it, types/functions from other headers show as undeclared.
How you generate it depends on the build system:

| Build system | How to produce `compile_commands.json` |
|---|---|
| CMake | `cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON` then `ln -s build/compile_commands.json .` |
| Make / other | install **bear** (`sudo apt install bear`), then `bear -- make` |
| None / simple | create a `compile_flags.txt` at the project root, one flag per line (e.g. `-std=c++17`, `-Iinclude`) |

After generating it, restart the language server: `:ALEStopAllLSPs` then reload the file
(`:e`), or just reopen Vim. Confirm with `:ALEInfo` (no "compilation database" warning).

**Tags (gutentags)** only run inside a recognised project root — a directory containing
`.git`, `CMakeLists.txt`, `Makefile`, or `package.json`. Outside one, `<C-]>` falls back
to the local `./tags;,tags;` only.

### Vim build & directories
- Needs a Vim with `+terminal` (glow preview), `+python3`, `+conceal`, `+folding`.
- This build is `-clipboard`; the system clipboard is handled by **vim-wsl-copy-paste**
  (requires WSL with Windows interop — uses `clip.exe` / `powershell.exe`).
- Cache dir for generated tags: `mkdir -p ~/.cache/vim/gutentags`.

## Markdown — vim-markdown + glow preview

| Key / Command | Action |
|---|---|
| `<leader>mp` | **Open/refresh a side-by-side rendered preview** (glow, in a vertical split) |
| `<leader>mq` | Close the preview |
| `<leader>mc` | Toggle inline rendering (conceal) on/off |
| `:Toc` | Open a table-of-contents split |
| `:TableFormat` | Align the markdown table under the cursor (uses tabular) |
| `]]` / `[[` | Next / previous header **(default)** |
| `]c` | Go to current header **(default)** |
| `]u` | Go to parent header **(default)** |

*(All of the above are active in markdown buffers only.)*

**Preview** (`,mp`): renders the file with `glow` in a right-hand split and
**auto-refreshes every time you save** (`:w`). To scroll it, move into the split
(`<C-w>l`); close it with `,mq`. Requires the `glow` binary on your `PATH`
(installed at `~/.local/bin/glow`).

**Inline rendering** (`,mc`): conceals raw markup (`**bold**`, `[links](url)`,
etc.) and styles it in place; the line under the cursor stays raw for editing.

> **Note on headers in the preview:** glow keeps the `##`/`###` markers on H2+
> headings *on purpose* — a terminal can't change font size, so the `#` count is
> the cue for heading depth. Only H1 gets a colored banner with its `#` stripped.
> This is glow's design, not a bug.

## Tags — vim-gutentags **(automatic)**
Regenerates the ctags `tags` file in the background whenever you open or save a
file inside a project (a dir containing `.git` / `CMakeLists.txt` / `Makefile` /
`package.json`). Generated files live in `~/.cache/vim/gutentags/`, so your
project dirs stay clean. This powers `<C-]>` / `g<C-]>` / `:Tags` with no manual
`ctags -R`. Toggle it per-session with `:GutentagsToggleEnabled`.

---

## Status line — lightline
Always-on status bar at the bottom (mode, file, git branch, position). No mappings. **(automatic)**

Shows **`TAGS...`** on the right-hand side while gutentags is regenerating tags in
the background; it disappears once indexing finishes.
